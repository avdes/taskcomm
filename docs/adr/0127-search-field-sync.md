# 0127. Синхронизация полей поиска: грамматика пути и место при старте

- **Дата:** 2026-10-24
- **Статус:** принято

## Контекст

[0037](0037-search-field-registry.md) велит при старте проверять форму объявления поля поиска —
«непустое имя, разбираемый путь» — и синхронизировать объявления в `tc_searchable_field`. Что
такое разбираемый путь, не сказано; в примерах встречаются `$.orderId` и `$.customer.inn`. Путь
потом подставляется в SQL поиска как `payload#>>'{a,b}'`.

## Рассмотренные варианты

- **A. `$.имя(.имя)*`, имя — `[A-Za-z_][A-Za-z0-9_]*` — выбрано.** Без массивов и кавычек: путь
  подставляется в SQL без экранирования, и узкая грамматика исключает инъекцию по построению.
- **B. Плюс индексы массивов `[0]`** — отвергнуто: частичный индекс по элементу массива редко
  имеет смысл, разбор сложнее. Расширить грамматику можно позже, не ломая объявленного.

## Решение

- Путь — `$` и одно или больше имён через точку; имя — латинская буква или подчёркивание, затем
  буквы, цифры, подчёркивания. Пустое имя поля или путь вне грамматики — падение при старте
  с типом задачи, уровнем и именем поля в сообщении.
- Объявления собирает реестр процессоров при своей сборке: по уровням контракта — у плоского
  процессора поля задачи, у процессора с подзадачами ещё поля подзадачи, у процессора с группами
  поля группы и подзадачи.
- Синхронизация — бин подготовки задач, после проверки схемы и до движка, одной транзакцией:
  `INSERT ... ON CONFLICT` по уникальному ограничению сигнатуры; `last_declared_at` двигается
  всегда, оформление приводится к объявленному, `updated_at` — только если оформление изменилось.
  `taskcomm.search.remove-undeclared-fields` удаляет строки, которых нет среди объявлений,
  с WARN на каждую.
- Тем же бином при старте печатается предупреждение об осиротевших задачах с числом незавершённых
  по типу ([0026](0026-contract-shape-marking.md)).

## Последствия

- Ошибка в пути видна при деплое, а не при первом поиске.
- Пути с дефисом, пробелом или индексом массива объявить нельзя, пока грамматику не расширят.
- Проверка наличия индексов под поиск и печать DDL остаются этапу поиска.

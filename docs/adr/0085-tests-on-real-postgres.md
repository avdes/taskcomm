# 0085. Интеграционные тесты — на настоящем PostgreSQL в Testcontainers; `initialize` по умолчанию `never`

- **Дата:** 2026-10-20
- **Статус:** принято
- **Изменено:** [0108](0108-integration-test-task.md) — `*IT` запускаются своей задачей
  `integrationTest` в составе `check`, `test` — только `*Test`.

## Контекст

Критерий готовности этапа схемы в roadmap — «тест на H2/Testcontainers поднимает схему с нуля».
H2 для этого непригоден в принципе: он не умеет ничего из того, на чём стоит схема, —
декларативное партиционирование и `ATTACH PARTITION` ([0078](0078-partition-maintenance.md)),
`jsonb` ([0012](0012-payload-storage.md)), `FOR UPDATE SKIP LOCKED` с семантикой PostgreSQL
([0006](0006-lease-based-claiming.md)), `pg_advisory_xact_lock`
([0077](0077-external-infrastructure-optional.md)), частичные индексы в нужной форме. Тест на H2
проверял бы другую СУБД.

Рядом обнаружилось второе: `taskcomm.schema.initialize` по [0013](0013-database-schema.md) имеет
значение по умолчанию `embedded`, по образцу `spring.sql.init.mode`. Spring считает базу встроенной
по драйверу — H2, HSQLDB, Derby. PostgreSQL встроенным не бывает никогда, в том числе
в Testcontainers, а схема у нас только для PostgreSQL. Значит, значение по умолчанию на деле
равно `never`, а читается как «включено для тестов».

## Рассмотренные варианты

### База для тестов

#### A. Testcontainers — выбрано

Настоящий PostgreSQL нужной версии в Docker, штатная поддержка в Spring Boot 3.5
(`@ServiceConnection`), зависимость только тестовая. Цена — Docker на машине разработчика
и в CI; он есть.

#### B. Встроенный PostgreSQL (`io.zonky.test:embedded-postgres`) — отвергнуто

Docker не нужен, но версии бинарников отстают от выпусков PostgreSQL, а на Windows сборка
капризнее, чем на Linux.

#### C. H2 — отвергнуто

Причины — в «Контексте».

### Значение `initialize` по умолчанию

#### i. `never`, для тестов и локальной разработки — явно `always` — выбрано

#### ii. Оставить `embedded` ради единообразия со Spring — отвергнуто

Привычное имя, но значение по умолчанию, которое не срабатывает никогда, вводит в заблуждение
сильнее, чем непривычное.

## Решение

- **Интеграционные тесты (`*IT`) идут на PostgreSQL в Testcontainers.** H2 и прочие встроенные
  базы в тестах стартера не используются. Версия Testcontainers приходит из BOM Spring Boot,
  отдельно не пинится. Зависимость — только в тестовой конфигурации, потребителям не приезжает.
- **Docker обязателен для полного прогона** локально и в CI. Модульные тесты (`*Test`) от него
  не зависят.
- **`taskcomm.schema.initialize` по умолчанию `never`.** Набор значений прежний —
  `never` | `embedded` | `always`; `embedded` остаётся ради совпадения со Spring, и документация
  обязана сказать, что на PostgreSQL оно не срабатывает. Для тестов и локальной разработки
  ставится `always`.

## Последствия

- **Тесты проверяют ту СУБД, на которой работает стартер**, включая партиции, блокировки
  и `SKIP LOCKED`.
- **Полный прогон без Docker невозможен.** Это условие среды разработки, и о нём сказано в CLAUDE.md.
- **Тесты медленнее**: контейнер поднимается на класс или на прогон; переиспользование
  контейнера между классами — дело тестовой инфраструктуры.
- **Продовая схема по умолчанию стартером не создаётся никогда**, и это теперь видно из самого
  значения, а не из знания о том, как Spring определяет встроенную базу.

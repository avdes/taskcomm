# 0115. Доля FIFO у формы `quota` — жребий на каждый захват

- **Дата:** 2026-10-24
- **Статус:** принято

## Контекст

Форма захвата `quota` — строгий приоритет, но «заданная доля захватов» идёт по чистому FIFO,
мимо приоритета ([0063](0063-claim-ordering-and-pollers.md)). Ни имени настройки, ни значения
по умолчанию, ни механики 0063 не задал — сказал только, что при нескольких экземплярах доля
соблюдается статистически.

Захват берёт не больше свободных воркеров ([0083](0083-claim-limited-by-free-workers.md)), и при
загруженном пуле это часто одна строка.

## Рассмотренные варианты

- **A. Жребий на каждый захват — выбрано.** С вероятностью доли весь захват идёт по
  `next_attempt_at`, иначе — по `priority, next_attempt_at`. Один запрос, один индекс на захват.
- **B. Деление пачки** — `round(доля × лимит)` строк по FIFO, остальное по приоритету — отвергнуто.
  Два прохода с исключением повторов, а при лимите в одну строку деление вырождается в округление:
  доля 0,1 даёт ноль FIFO-захватов навсегда.

## Решение

- Настройка **`fifo-share`** у поллера — `taskcomm.task.poll.fifo-share` и у выделенных поллеров;
  по умолчанию **0,1**. Допустимо строго между 0 и 1: ноль — это форма `priority`, единица —
  чистый FIFO, ради которого `quota` не нужна. Вне интервала — падение при старте.
- Каждый захват при `quota` бросает жребий: выпало меньше доли — порядок FIFO по частичному
  индексу `(status, next_attempt_at)`, иначе — порядок `priority` по
  `(status, priority, next_attempt_at)`.

## Последствия

- Доля соблюдается статистически и на одном экземпляре, а не только на нескольких: короткая серия
  захватов может не дать ни одного FIFO.
- Источник случайности подставляется в тестах — порядок проверяется детерминированно.
- У коммуникаций своя форма `quota` появится на этапе 5 своими настройками
  ([0010](0010-separate-engines.md)); имя `fifo-share` естественно повторить.

## Связанные решения

- [0083](0083-claim-limited-by-free-workers.md) — захват не больше свободных воркеров.

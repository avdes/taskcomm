# 0116. Лимит попыток — свой у каждой фазы

- **Дата:** 2026-10-24
- **Статус:** принято

## Контекст

Попытки в лимите считаются по строкам `tc_task_attempt` начиная с `retry_cycle_started_at`
сущности ([0043](0043-manual-restart-resets-attempts.md)). Настройки повторов при этом свои
у каждой фазы — `PROCESS`, `EXPAND`, `COLLECT` ([0060](0060-retry-and-lease-configuration.md),
[0061](0061-processor-configuration-annotations.md)). Какие строки входят в счёт, правило
не уточняло, и буквальное чтение — все строки цикла.

При счёте по всем фазам у родителя успешное раскрытие съедает попытку сборки: при
`max-attempts: 2` на сборку остаётся одна попытка, а лимит раскрытия зависит от того, сколько
раз падала уже другая работа.

## Рассмотренные варианты

- **A. Все попытки цикла, лимит фазы текущей попытки** — отвергнуто. Лимит фазы перестаёт
  означать то, что в нём написано, и зависит от истории других фаз.
- **B. Попытки той же фазы — выбрано.** Лимит фазы считает только её попытки.

## Решение

Попытки в лимите считаются по строкам попыток **той же фазы**, что закрытая неуспешная попытка,
начиная с `retry_cycle_started_at` сущности. Лимит берётся из настроек этой фазы. Ручной
перезапуск по-прежнему сдвигает отметку и обнуляет счёт всех фаз сразу.

## Последствия

- `max-attempts` фазы означает ровно число её попыток в цикле.
- Родитель в худшем случае делает сумму лимитов своих фаз попыток за цикл, а не один общий
  лимит.
- Запрос счёта получает условие по `phase`; индекс `(level, target_id, started_at)` его ведёт,
  строк у одной сущности десятки.
- Комментарий к `retry_cycle_started_at` в схеме 2.0.0 о фазе не говорит; он не ложен, но неполон,
  и правится вместе со следующей миграцией.

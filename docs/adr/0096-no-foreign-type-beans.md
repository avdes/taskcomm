# 0096. Стартер не регистрирует бины чужих типов; точки замены — бины потребителя с квалификатором

- **Дата:** 2026-10-21
- **Статус:** принято

## Контекст

[0089](0089-no-storage-spi-explicit-extension-points.md) оставил под `@ConditionalOnMissingBean`
только бины публичных типов — из `api` стартера или чужих библиотек: `ObjectMapper` нагрузки,
планировщик, пул воркеров, `RequestMatcher`. Условие срабатывает по типу, а это ровно те типы,
которыми пользуется само приложение и автоконфигурации Spring Boot:

- **`ObjectMapper` / `JsonMapper`.** Наш бин, объявленный раньше `JacksonAutoConfiguration`,
  вытесняет маппер приложения. Объявленный позже — отступает сам, и нагрузка пишется маппером веб-слоя:
  смена его naming strategy молча меняет формат хранимых данных. Оба сразу — получение `ObjectMapper`
  по типу в коде потребителя падает на неоднозначности.
- **`TaskScheduler`.** Наш бин вытесняет планировщик Spring Boot, и `@Scheduled` потребителя
  выполняется на наших потоках.
- **`Executor`.** Бин этого типа по умолчанию отключает `applicationTaskExecutor` Spring Boot,
  на котором висят `@Async` и асинхронный MVC.
- **`RequestMatcher`.** Любой бин этого типа у потребителя молча отключает наш.

По сути это то же включение глобальных механизмов за потребителя, что CLAUDE.md запрещает для
`@EnableScheduling`. Вдобавок `TaskcommProperties` стоит под `@ConditionalOnMissingBean`, хотя
в списке точек замены его нет.

Отдельно — пул воркеров. Пул у каждого поллера свой, размером `workers`
([0063](0063-claim-ordering-and-pollers.md)), и захват берёт не больше свободных воркеров этого
пула ([0083](0083-claim-limited-by-free-workers.md)). Один заменяемый бин `Executor` не может быть
несколькими пулами разного размера, а чужой `Executor` с очередью скрывает число свободных
воркеров.

## Рассмотренные варианты

### Механизм

#### A. Свои публичные типы-обёртки — отвергнуто

Кодек нагрузки, свой интерфейс пула. Ни с чем не сталкиваются. Отвергнуто: кодек нагрузки —
новый SPI с методами сериализации, замороженный там, где потребителю нужно лишь донастроить
Jackson.

#### B. Не регистрировать бины чужих типов, замена — бином потребителя с квалификатором — выбрано

Маппер, планировщик и пулы создаются внутри внутренних бинов стартера и принадлежат им вместе
с остановкой. Стартер берёт бин потребителя, помеченный своим квалификатором, через
`ObjectProvider`; нет такого — создаёт своё. Ничего не вытесняется ни при каком порядке
автоконфигураций. Тот же приём квалификаторов, что в [0094](0094-creation-always-in-transaction.md).

#### C. Регистрировать под своими именами с `@Bean(defaultCandidate = false)` — отвергнуто

Механизм Spring 6.2: такой бин не участвует во внедрении по типу. Отвергнуто: корректность
держалась бы на том, как `@ConditionalOnMissingBean` Spring Boot и поиск планировщика в
`ScheduledAnnotationBeanPostProcessor` обходятся с такими бинами, — тонкостях фреймворка,
не проверенных на наших версиях.

### Маппер нагрузки

#### D. Точка замены с квалификатором — выбрано

Без бина потребителя стартер создаёт свой маппер с постоянной конфигурацией, не зависящей
от веб-слоя. С бином — берёт его: модули, mixin-ы для чужих классов, свои сериализаторы.

#### E. Без замены вовсе — отвергнуто

Нагрузка настраивается только аннотациями Jackson на своих классах, модули — через
`ServiceLoader`. Формат стабилен по построению, но mixin-ы для классов, которые потребитель
не может пометить аннотациями, недоступны.

### Пул воркеров

#### F. `ThreadFactory` с квалификатором — выбрано

Пулы создаёт стартер, по одному на поллер, размером `workers`; счёт свободных воркеров
не меняется. Потребитель управляет созданием потоков.

#### G. `TaskDecorator` с квалификатором — выбрано

Оборачивает каждый запуск работы: контекст трассировки, свои thread-local. MDC стартер снимает
сам ([0034](0034-mdc-business-id.md)), декоратор — для остального.

#### H. Готовый `Executor` с квалификатором вместо всех пулов — отвергнуто

Ломает размеры пулов по поллерам и счёт свободных воркеров из 0083: захваченное снова ждало бы
в чужой очереди, держа аренду.

### `RequestMatcher` и `TaskcommProperties`

#### I. Убрать из точек замены — выбрано

`RequestMatcher` стартер отдаёт потребителю, а не берёт у него: заменять его бессмысленно, свою
цепочку безопасности потребитель пишет сам. Подмена бина свойств в Spring Boot не принята.

#### J. Оставить — отвергнуто

`@ConditionalOnMissingBean(RequestMatcher.class)` молча отключает наш бин при любом
`RequestMatcher` у потребителя.

## Решение

- **Стартер не регистрирует бинов чужих типов**, которые потребляет сам: ни `ObjectMapper` /
  `JsonMapper`, ни `TaskScheduler`, ни `Executor`, ни `ThreadFactory`, ни `TaskDecorator`.
  Маппер, планировщик и пулы — поля внутренних бинов, и их остановка — забота этих бинов.
- **Точки замены — бины потребителя с квалификатором стартера**, все необязательны:

  | Квалификатор | Тип бина | Что заменяет |
  |---|---|---|
  | `@TaskcommPayloadMapper` | `JsonMapper` (Jackson 3) | маппер нагрузки, результатов и доменных форм обмена |
  | `@TaskcommScheduler` | `TaskScheduler` | планировщик тактов поллеров, heartbeat, обслуживания партиций, подстраховочных поллеров |
  | `@TaskcommWorkerThreadFactory` | `ThreadFactory` | создание потоков во всех пулах воркеров |
  | `@TaskcommWorkerTaskDecorator` | `TaskDecorator` | обёртку каждого запуска работы воркером |

  Помеченных бинов одного квалификатора больше одного — падение при старте. Квалификаторы
  лежат в `autoconfigure`, как в 0094.
- **Пулы воркеров создаёт только стартер**, по одному на поллер, размером `workers`. Готовый
  `Executor` подставить нельзя.
- **`RequestMatcher` — единственный бин чужого типа**, и это бин, который стартер отдаёт,
  а не потребляет: регистрируется под именем `taskcommRequestMatcher`, без условий, вместе с REST
  ([0091](0091-rest-disabled-by-default.md)).
- **`TaskcommProperties` и прочие классы свойств — без `@ConditionalOnMissingBean`.**
- **Чужой планировщик проверяется при старте**: если по нему видно число потоков и оно меньше
  двух — громкое предупреждение. На нём идут heartbeat и такты: занятый планировщик задерживает
  продление аренды, а задержка продления — двойное выполнение.
- Тест автоконфигурации «бин потребителя перекрывает наш» — по одному на каждый квалификатор
  из таблицы, плюс тест, что без квалификатора бины потребителя этих типов стартером
  **не берутся** и бинов этих типов стартер в контекст не добавляет.

## Последствия

- **Подключение стартера не меняет поведения приложения**: `@Scheduled`, `@Async`,
  асинхронный MVC и маппер веб-слоя остаются такими, какими были.
- **Формат нагрузки не зависит от настроек веб-слоя.** Меняется он только помеченным маппером,
  и это видно в коде потребителя.
- **Четыре новых публичных типа навсегда** — квалификаторы.
- **`JsonMapper` становится частью договорённости с потребителем** как тип бина под
  `@TaskcommPayloadMapper`. Правило [0092](0092-jackson-3-liquibase-compatibility.md) «типы
  Jackson в публичный API не попадают» остаётся в силе для сигнатур Java; для этой точки замены
  оно сознательно нарушено, и переход на следующую ветку Jackson ломает бины потребителей
  с этим квалификатором.
- **Помеченный маппер меняет формат хранимой нагрузки.** Сменить его конфигурацию у работающей
  системы — то же, что переименовать поле в классе нагрузки; это пишется в consumer-contract.
- **Готовый пул потребителя подставить нельзя**: виртуальные потоки и своя очередь недоступны
  иначе, чем через `ThreadFactory`.
- **Предупреждение о планировщике видит не всё**: по произвольной реализации `TaskScheduler`
  число потоков не узнать, и тогда проверки нет.

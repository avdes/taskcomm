# 0103. Интервал heartbeat не меньше аренды — падение при старте

- **Дата:** 2026-10-21
- **Статус:** принято

## Контекст

[0025](0025-lease-mechanics.md) решил, что соотношение интервала heartbeat и длительности аренды
при старте проверяется только предупреждением: «неверная настройка проявится не при старте, а под
нагрузкой». [0060](0060-retry-and-lease-configuration.md) включил его в общий набор проверок
как `heartbeat-interval > duration / 3`, в разряд «плохие, но рабочие соотношения». Падения нет
ни при каком значении.

Но при `heartbeat-interval ≥ duration` соотношение не плохое, а нерабочее: аренда истекает раньше
первого продления. Каждая попытка, которая длится дольше аренды, закрывается `LEASE_LOST`
([0067](0067-expired-lease-closes-attempt.md)), работу подбирает другой экземпляр, и двойное
выполнение гарантировано — без единой ошибки в логе.

Граница проверок в 0060 и в правилах — «способна ли система вообще работать с этим значением»:
бессмысленные по построению значения роняют старт, плохие, но рабочие — предупреждают. Этот
случай по ней — падение.

## Рассмотренные варианты

### A. Падение при `heartbeat-interval ≥ duration`, предупреждение при `> duration / 3` — выбрано

Порог «гарантированно не работает» совпадает с границей проверок.

### B. Падение уже при `≥ duration / 2` — отвергнуто

Там один пропущенный такт даёт потерю аренды. Отвергнуто: с таким значением система работает,
пока такты не пропускаются, — хрупко, но рабочее; для этого и есть предупреждение.

### C. Оставить предупреждение — отвергнуто

Противоречит собственному критерию проверок.

### D. Молча исправлять интервал на `duration / 3` — отвергнуто

Стартер переписал бы конфигурацию эксплуатации — та же ловушка, которую
[0061](0061-processor-configuration-annotations.md) отверг для порядка разрешения: настройка
молча не применяется, и вопрос «почему у меня такое значение» остаётся без ответа.

## Решение

- **Падение при старте, если `heartbeat-interval ≥ duration`** — для каждого итогового значения
  `duration` после разрешения по пяти уровням (0061): по каждому типу задачи или внешней системе
  и по каждой фазе. Heartbeat один на экземпляр и продлевает все аренды одним тактом (0025),
  а длительность аренды переопределяется по типу и фазе — поэтому проверка идёт по каждой паре.
- Сообщение называет тип, фазу, уровень, с которого взято значение `duration`, и рекомендуемый
  интервал — не больше `duration / 3`.
- **Предупреждение при `heartbeat-interval > duration / 3`** остаётся, громкое и с рекомендуемым
  значением (0025, 0060), — для всех значений между третью аренды и самой арендой.

## Последствия

- **Конфигурация, при которой двойное выполнение гарантировано, не стартует.**
- **Переопределение аренды по фазе может уронить старт**: короткая аренда на фазе `PROCESS` при
  глобальном интервале heartbeat — частый путь к этому падению, и сообщение обязано указать уровень.
- Хрупкие, но рабочие значения по-прежнему только предупреждают.

# Журнал архитектурных решений (ADR)

Каждый файл — одно решение: что решили, какие были варианты, почему выбрали этот и чем за это
платим. Файлы отвечают на вопрос **«почему оно так»**, а не «как это работает».

## Правила ведения

- Один файл — одно решение. Номер присваивается по порядку и никогда не переиспользуется.
- **Принятый ADR не редактируется по существу.** Передумали — пишем новый и помечаем старый как
  заменённый, со ссылкой. История решений так же ценна, как само решение: она не даёт вернуться
  к отвергнутому варианту по кругу.
- Единственная допустимая правка принятого ADR — **добавление строки в шапку**. Без этого механизм
  замены не работал бы вовсе: читатель старого файла не узнал бы, что его отменили.
  - `**Изменено:**` — новое решение меняет часть старого, а не всё целиком. Со ссылкой.
  - `**Поправка:**` — в тексте ADR обнаружена фактическая ошибка, не затрагивающая само решение.
    Тело не переписывается: ошибочная формулировка остаётся, рядом появляется верная. Переписать
    молча значило бы скрыть, что документ какое-то время вводил в заблуждение.
- Статус: `принято` | `заменено ADR-NNNN` | `отложено`.
- Раздел «Рассмотренные варианты» обязателен и должен содержать отвергнутые. ADR без них
  бесполезен — именно они объясняют, почему нельзя «просто сделать проще».
- Раздел «Последствия» тоже обязателен, включая неприятные. Решение без цены — это не решение.

## Шаблон

```markdown
# NNNN. Заголовок решения

- **Дата:** ГГГГ-ММ-ДД
- **Статус:** принято

## Контекст
Что заставило принимать решение. Ограничения, которые нельзя обойти.

## Рассмотренные варианты
### A. Название
Суть. Плюсы. Минусы.
### B. Название
...

## Решение
Что выбрали и почему именно это.

## Последствия
Что теперь обязаны делать, что стало нельзя, чем платим.

## Связанные решения
[NNNN](NNNN-slug.md) — как связаны.
```

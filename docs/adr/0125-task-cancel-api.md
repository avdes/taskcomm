# 0125. Отмена в `TaskService` и её результат

- **Дата:** 2026-10-24
- **Статус:** принято

## Контекст

Механика отмены решена в [0070](0070-cancellation-on-any-entity.md) и
[0100](0100-cancel-keeps-real-outcome.md), но точки входа у неё не было: форма публичного API
задач ([0111](0111-task-public-api-shape.md)) метода отмены не содержала, а отмена через REST
стоит на этапе REST. Не было решено и что делать с отменой уже терминальной сущности.

## Рассмотренные варианты

### Где вход

- **A. Только внутренний сервис, публичный вход — через REST.** Отвергнуто: потребитель не мог бы
  отменить задачу из своего кода, не включая REST.
- **B. Метод в `TaskService` — выбрано.** Аддитивное изменение публичного API.

### Терминальная сущность

- **A. Ставить флаг как факт «здесь нажали отмену»** — отвергнуто: флаг навсегда запрещает
  перезапуск ([0071](0071-no-restart-after-cancel.md)), и `SUCCEEDED` с флагом закрыл бы его
  без всякой пользы.
- **B. Отказ, флаг не ставится — выбрано.**

### Как сообщается исход

- **A. `boolean`** — `false` у терминальной и уже отменённой. Отвергнуто: «почему нет» теряется,
  а «принята» не говорит, отменена ли сущность сразу или доиграет работу.
- **B. `void` и исключение** — отвергнуто: гонка «сущность завершилась между чтением и отменой» —
  обычный исход, ловить его исключением неудобно.
- **C. Запечатанный результат с причиной — выбрано.**

## Решение

```java
TaskCancelResult cancel(Task<?> task);
TaskCancelResult cancel(TaskBatch<?> batch);
TaskCancelResult cancel(TaskUnit<?> unit);

public sealed interface TaskCancelResult {
    boolean accepted();
    String reason();
    record Accepted(String reason) implements TaskCancelResult { }
    record Rejected(String reason) implements TaskCancelResult { }
}
```

- Перегрузки по типу сущности: сущность уже несёт идентификатор и дело, партиция отсекается
  по `executionRef().createdAt()`.
- **`Accepted`** — отметка поставлена. Причина говорит, что дальше: «отменена сразу» у
  `PENDING` и `AWAITING_PARENT`, «доиграет и запишет настоящий исход» у `RUNNING`, «станет
  `CANCELLED`, когда закончатся потомки» у `AWAITING_CHILDREN`.
- **`Rejected`** — отметка не ставилась: сущность в терминальном статусе (причина называет его),
  уже отменена или не найдена.
- Отметка ставится под блокировкой строки сущности, в той же транзакции не начинавшаяся сущность
  становится `CANCELLED`; перевод потомков — после коммита, пачками.

## Последствия

- `TaskService` получил три метода — изменение аддитивное, мажорной версии не требует.
- Отмена группы и подзадачи доступна, только если у потребителя есть их объекты; методов
  чтения групп и подзадач в `TaskService` пока нет — их добавит отдельное решение.
- REST вызовет ту же механику и превратит `Rejected` в ошибку клиента.

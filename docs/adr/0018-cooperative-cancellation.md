# 0018. Кооперативная отмена

- **Дата:** 2026-08-27
- **Статус:** принято
- **Изменено:** [0025](0025-lease-mechanics.md) — сигнал контекста расширен: он означает
  «прекращай», а не только «тебя отменили». Потеря аренды выражается тем же сигналом.

## Контекст

Отмена задачи входит в состав REST API ([0014](0014-rest-api.md)). Сложность в том, что часть
подзадач в момент отмены может быть в статусе `RUNNING` — то есть прямо сейчас исполняться внутри
процессора потребителя.

## Рассмотренные варианты

### A. Отменять только `PENDING` — отвергнуто

Максимально просто. Отвергнуто по поведению: пользователь отменил задачу, а она продолжает работать
ещё час, и по интерфейсу непонятно, почему. Отмена, которая не отменяет, хуже отсутствия отмены.

### B. Кооперативная отмена — выбрано

Задача помечается отменённой немедленно, новые подзадачи в работу не берутся, уже выполняющиеся
доигрывают до конца. Процессору доступен способ узнать, что его отменили, и завершиться раньше —
добровольно.

### C. Прерывание потока — отвергнуто

`Thread.interrupt` в процессор потребителя. Быстро и решительно, но прерывание чужого кода
в произвольной точке оставляет данные в половинчатом состоянии: процессор мог отправить запрос
во внешнюю систему и не успеть записать результат. Для библиотеки, которая не знает, что делает
процессор, это недопустимо.

## Решение

Отмена **кооперативная**.

- Статус проставляется сразу, новые подзадачи не захватываются.
- Уже захваченные доигрывают. Задача считается окончательно отменённой, когда ни одной `RUNNING`
  не осталось.
- Процессор может спросить, отменили ли его, через контекст выполнения. Проверка добровольная:
  процессор, который её не делает, просто доработает до конца.

## Последствия

- Между «отменил» и «действительно остановилось» проходит время, и его длительность определяется
  чужим кодом. Интерфейс обязан различать «отмена запрошена» и «отменено», иначе пользователь
  решит, что отмена не сработала.
- **Подзадача, успешно завершившаяся уже после отмены, записывается как `SUCCEEDED`, а не
  `CANCELLED`.** Она реально выполнилась, её побочные эффекты существуют, и скрывать это опасно:
  по истории должно быть видно, что во внешнюю систему что-то ушло.
- Отмена **не гарантирует**, что во внешние системы ничего не отправлено. Это надо писать
  в документации прямо: отмена останавливает планирование, а не последствия.
- Проверка отмены — часть публичного контракта контекста выполнения, доступного процессору.
  Она добровольная, но её наличие обязывает нас поддерживать её вечно.

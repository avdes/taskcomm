# 0107. Код схемы — в пакете `schema.internal`

- **Дата:** 2026-10-24
- **Статус:** принято

## Контекст

Этап схемы приносит не только DDL и changelog — они лежат в ресурсах
([0013](0013-database-schema.md)), — но и Java-код, которому ресурсы не замена:

- проверку схемы при старте с внятным сообщением;
- обслуживание партиций — создание через `LIKE` и `ATTACH`, удаление под блокировкой, очистку
  реестра корреляции ([0078](0078-partition-maintenance.md), [0080](0080-partition-configuration.md));
- границу активных партиций — расчёт при старте и сдвиг на такте
  ([0101](0101-active-partition-horizon.md));
- `taskcomm.schema.initialize` — инициализатор, накатывающий тот же DDL
  ([0085](0085-tests-on-real-postgres.md)).

Этот код не принадлежит ни одной подсистеме: партиция одного диапазона общая для девяти таблиц
задач, коммуникаций и дел, и настройки у неё одни на всю схему. В структуре пакетов места для него
не было: `task` и `communication` друг от друга изолированы ([0010](0010-separate-engines.md)),
`execution` объявлен пассивным ([0038](0038-execution-aggregate.md)), `autoconfigure` — только
`@AutoConfiguration` и свойства.

## Рассмотренные варианты

### A. Новый пакет `schema.internal` — выбрано

Свой пакет без `api`: потребитель с этим кодом не работает, только настраивает его свойствами.
Зависимостей на подсистемы у него нет — с их таблицами он работает SQL-ом, а не их классами.

### B. `execution.internal` — отвергнуто

Пакет уже общий для обеих подсистем, а ключ партиционирования — время создания дела. Но агрегат
пассивен по определению, а здесь появился бы активный такт по расписанию и SQL по таблицам
подсистем. Исключение 0087 для `execution.internal` заведено ради держателя текущего дела
и расширять его молча нельзя.

### C. `autoconfigure` — отвергнуто

Пакет перестал бы быть только сборкой бинов, и внутренние классы оказались бы рядом с публичными
квалификаторами и свойствами.

## Решение

- Внутренний код схемы живёт в **`xyz.avasilev.taskcomm.schema.internal`**. Пакета
  `schema.api` нет.
- Правила ArchUnit дополняются ([0087](0087-architecture-rules.md)):
  - `schema.internal` используется только из `schema..` и `autoconfigure..`;
  - `schema..` не зависит ни от `task..`, ни от `communication..`, ни от `execution..`.

## Последствия

- Код схемы виден в структуре проекта отдельно от подсистем, и изоляция подсистем не страдает.
- **Подсистемы не могут вызвать код схемы напрямую.** Оживление партиции
  ([0101](0101-active-partition-horizon.md)) — путь записи подсистемы, и его SQL подсистема
  пишет сама; общего Java-класса для него нет — это то самое дублирование, которое требует
  [0010](0010-separate-engines.md).
- Правило «каждая подсистема выключается своим `enabled`» на схему не распространяется: своего
  выключателя у неё нет, её выключает только корневой `taskcomm.enabled`
  ([0090](0090-root-switch-disables-everything.md)) и `partitions.manage: false` — для DDL.

## Связанные решения

- [0087](0087-architecture-rules.md) — правила ArchUnit, здесь дополненные.
- [0010](0010-separate-engines.md), [0038](0038-execution-aggregate.md) — почему не в пакеты
  подсистем и не в `execution`.
- [0078](0078-partition-maintenance.md), [0080](0080-partition-configuration.md),
  [0101](0101-active-partition-horizon.md) — что этот код делает.

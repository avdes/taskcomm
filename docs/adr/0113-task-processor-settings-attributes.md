# 0113. Атрибуты `@TaskProcessorSettings` и аннотации-сокращения

- **Дата:** 2026-10-24
- **Статус:** принято

## Контекст

[0066](0066-processor-settings-annotation-names.md) назвал аннотацию настроек процессора задач
и оставил её состав на этап публичного API. Аннотация задаёт всё, что `yaml` на уровне типа:
приоритет, аренду, предел обработки, повторы ([0061](0061-processor-configuration-annotations.md)),
причём приоритет — только на классе ([0084](0084-priority-only-per-type.md)).

У атрибута аннотации нет значения «не задано»: `null` недопустим. Нужен способ отличить
незаданный атрибут от заданного, иначе аннотация перекрывала бы `yaml`-умолчания своими.

## Рассмотренные варианты

- **A. Вложенные аннотации по дереву `yaml`** (`lease = @TaskLease(...)`) — отвергнуто.
  Имена совпадают с `yaml`, но частый случай — одна настройка — пишется длиннее.
- **B. Плоская аннотация со всеми атрибутами — выбрано**, вместе с аннотациями-сокращениями
  для групп настроек.

## Решение

- **`@TaskProcessorSettings`** — плоская, девять атрибутов: `priority`, `leaseDuration`,
  `heartbeatInterval`, `maxExecutionTime`, `maxAttempts`, `initialDelay`, `multiplier`, `maxDelay`,
  `jitter`. Длительности — строки в формате `Duration` Spring Boot (`"30m"`).
- **«Не задано» — ноль или пустая строка.** Для каждой настройки ноль и так недопустим:
  `priority > 0`, `max-attempts ≥ 1`, `multiplier ≥ 1`, `jitter` в `(0, 1]`, длительности
  положительны.
- **Сокращения `@TaskPriority`, `@TaskLease`, `@TaskRetry`** мета-аннотированы
  `@TaskProcessorSettings`, их атрибуты связаны с атрибутами основной через `@AliasFor`; стартер
  читает слитую аннотацию через `MergedAnnotations`. `@TaskPriority` вешается только на класс —
  это ловит компилятор.
- **Несколько аннотаций на одном классе или методе складываются**: берутся заданные атрибуты всех.
  Один и тот же атрибут задан дважды — падение при старте.
- Приоритет в `@TaskProcessorSettings` на методе — падение при старте, как решил 0084.

## Последствия

- Частый случай короток: `@TaskRetry(maxAttempts = 5)`.
- Имена атрибутов расходятся с деревом `yaml` (`lease.duration` → `leaseDuration`); печать
  итоговых настроек при старте ([0061](0061-processor-configuration-annotations.md)) называет
  уровень и источник и снимает путаницу.
- Аннотации опираются на `@AliasFor` из Spring — потребитель стартера и так на Spring.
- `@CommunicationProcessorSettings` получит свой состав на этапе 5, своими типами
  ([0010](0010-separate-engines.md)).

## Связанные решения

- [0066](0066-processor-settings-annotation-names.md) — имена аннотаций, здесь дополненные составом.
- [0061](0061-processor-configuration-annotations.md), [0084](0084-priority-only-per-type.md) —
  порядок разрешения и приоритет только на уровне типа.

# 0119. Постановка задачи типа без процессора отвергается

- **Дата:** 2026-10-24
- **Статус:** принято

## Контекст

Постановка по классу процессора без класса в реестре отвергается исключением
([0111](0111-task-public-api-shape.md)), постановка устаревшего типа — тоже
([0028](0028-contract-migration.md)). Что делать с постановкой по строке типа, которого нет
в реестре, решено не было. Задачи типов без процессора в схеме бывают — осиротевшие, после
удаления процессора, — и ждут его возвращения в `PENDING`.

## Рассмотренные варианты

- **A. Принять и оставить ждать процессора** — отвергнуто. Так можно было бы ставить задачи
  для другого сервиса, но одна схема обслуживает одно приложение
  ([0027](0027-schema-ownership.md)), а опечатка в имени типа превращалась бы в тихо зависшую
  задачу.
- **B. Отвергнуть исключением — выбрано.**

## Решение

`submit` по строке типа, которого нет в реестре процессоров, бросает `TaskcommException`
с именем типа. Задача не создаётся, дело тоже.

## Последствия

- Опечатка в имени типа видна в момент постановки.
- Осиротевшие задачи появляются только одним путём — процессор удалён после постановки, — и их
  видимость по-прежнему обеспечивают предупреждение при старте, метрика и REST
  ([0026](0026-contract-shape-marking.md)).
- Чтения задач типа без процессора тоже отвергаются: нагрузку и результат не во что разобрать.

## Связанные решения

- [0027](0027-schema-ownership.md) — одна схема, одно приложение.
- [0028](0028-contract-migration.md) — устаревший тип не принимает новых задач.
- [0111](0111-task-public-api-shape.md) — форма постановки.

# 0105. Коммуникации систем без процессора

- **Дата:** 2026-10-22
- **Статус:** принято

## Контекст

У задач правило для типов без процессора полное ([0026](0026-contract-shape-marking.md)):
в работу не берутся, состояния не меняют, вернули процессор — поехали дальше сами; видны тремя
каналами — громким предупреждением при старте, метрикой по типу и признаком в REST.

У коммуникаций — одна строка в [0054](0054-communication-attempt-lifecycle.md): открытая попытка
«у коммуникации, для чьей внешней системы нет процессора», — «норма, а не утечка». Не определено:

- создаётся ли коммуникация для системы, процессора которой нет;
- захватывается ли такая коммуникация и что делает воркер, которому некого вызвать;
- что с колбэком для такой системы ([0086](0086-async-response-in-outbound.md));
- видит ли это кто-нибудь. Документация потребителя в графе «Обнаружится?» для переименования
  внешней системы пишет «Да, зависают», а зависание и есть отсутствие обнаружения.

Случай штатный: внешнюю систему переименовали в `source` / `destination`, процессор удалили,
или при поэтапной выкатке старый экземпляр не знает новой системы.

## Рассмотренные варианты

### Создание для системы без процессора

#### A. Отказ исключением, для входящих и исходящих — выбрано

У входящих отказ неизбежен: тело разбирается при создании кодеком процессора системы
([0052](0052-communication-transport-contracts.md)), и без процессора разбирать нечем. У исходящих
отказ — по образцу постановки задачи `@Deprecated`-типа: создание из кода, где процессора нет, —
ошибка сборки потребителя, и узнать о ней лучше сразу. Поэтапная выкатка не задета: коммуникацию
создаёт экземпляр, в коде которого процессор уже есть.

#### B. Исходящие создаются и ждут процессора — отвергнуто

Выручило бы выкатку, где коммуникацию создаёт код без процессора в расчёте на другой экземпляр.
Отвергнуто: такой порядок выкатки сам по себе ошибка, а отказ показывает её сразу.

### Уже созданные

#### C. Как у задач: не захватываются, состояния не меняют, три канала видимости — выбрано

#### D. Захватывать и закрывать `FAILED` — отвергнуто

Вернуть процессор стало бы бесполезно: коммуникации уже терминальны. У задач этот вариант
отвергнут 0026 по той же причине.

## Решение

- **Создание коммуникации для системы без процессора отвергается исключением**, наследником
  `TaskcommException`, до записи чего-либо, — у входящих и у исходящих. Через REST — ошибка
  клиента.
- **Приём колбэка для системы без процессора** (`receiveResponse`) отвергается так же: тело
  колбэка разбирается кодеком процессора системы `source`, и разбирать нечем.
- **Уже созданные коммуникации систем без процессора не захватываются и состояния не меняют.**
  Захват исключает неизвестные системы условием `= ANY(:известные)`, как у задач исключаются
  неизвестные типы. Подстраховочные поллеры их тоже не трогают: истёкшее ожидание ответа не
  переводит такую коммуникацию на повторную отправку, которую некому выполнить. Вернули
  процессор — поехали дальше сами.
- **Видимость — тремя каналами, как у задач**:
  - громкое предупреждение при старте с перечнем систем и числом коммуникаций;
  - метрика осиротевших по внешней системе — в снимке метрик на всю схему
    ([0102](0102-schema-wide-metrics-snapshot.md));
  - признак в REST-выдаче.
- **Нагрузочный сценарий коммуникаций** ([0081](0081-claim-scan-filters-load-scenario.md), этап 5)
  включает осиротевшую систему с накопленной очередью.

## Последствия

- **Переименование внешней системы обнаруживается**: предупреждением при старте и метрикой,
  а не зависанием.
- **Код без процессора для системы не может её использовать** — ни отправить, ни принять.
- **Осиротевшие коммуникации читаются захватом и отбрасываются**, как осиротевшие задачи; их
  цену проверяет нагрузочный сценарий.
- **Ожидающая ответа коммуникация осиротевшей системы стоит в `AWAITING_RESPONSE`** и держит
  границу активных партиций ([0101](0101-active-partition-horizon.md)), как осиротевшая задача.
- Строка 0054 «открытая попытка у коммуникации без процессора — норма» остаётся верной и теперь
  объяснена правилом.

# 0108. Интеграционные тесты — своя задача `integrationTest` в составе `check`

- **Дата:** 2026-10-24
- **Статус:** принято

## Контекст

[0085](0085-tests-on-real-postgres.md) отправил интеграционные тесты (`*IT`) на PostgreSQL
в Testcontainers и записал: Docker обязателен для полного прогона, модульные тесты (`*Test`)
от него не зависят. Задача Gradle `test` по умолчанию запускает все тестовые классы, какое бы имя
у них ни было. Без отдельной настройки `gradlew.bat test --tests ...SomethingTest` работает,
а `gradlew.bat test` без Docker падает на первом `*IT` — вторая половина правила 0085
не выполнялась бы.

## Рассмотренные варианты

### A. Отдельная задача `integrationTest`, входит в `check` — выбрано

`test` запускает только `*Test`, `integrationTest` — только `*IT`, на том же наборе исходников
`src/test`. `build` по-прежнему полный и требует Docker.

### B. Отдельная задача вне `check` — отвергнуто

`build` проходил бы без Docker, но интеграционные тесты пришлось бы помнить запускать отдельно.
Про них забывали бы ровно тогда, когда они нужнее всего, — перед коммитом.

### C. Всё в `test` — отвергнуто

Модульные тесты нельзя прогнать без Docker, что противоречит 0085.

## Решение

- **`test` — только `*Test`; `integrationTest` — только `*IT`**, оба из `src/test`, один classpath.
- **`integrationTest` входит в `check`** и идёт после `test`. Полный прогон — по-прежнему
  `gradlew.bat build`.

## Последствия

- Модульные тесты гоняются без Docker: `gradlew.bat test`.
- `gradlew.bat build` без Docker падает на `integrationTest` — так и задумано 0085.
- Отдельного набора исходников (`src/integrationTest`) нет: разделение — по имени класса.
  Класс, названный не по правилу, не попадёт ни в одну задачу; имя `*Test` / `*IT` обязательно.

# 0083. Захват не больше свободных воркеров, следующий — сразу при освобождении

- **Дата:** 2026-10-20
- **Статус:** принято

## Контекст

Значения по умолчанию — `poll: { batch-size: 100, workers: 8 }` у обеих подсистем, а
[0060](0060-retry-and-lease-configuration.md) требует предупреждать при `batch-size > workers`.
Стартер с настройками по умолчанию ругается на себя на каждом старте; такое предупреждение
перестают читать, и вместе с ним остальные.

По существу 0060 прав. Строки, захваченные сверх свободных воркеров, ждут в памяти экземпляра,
и пока ждут:

- **свободный экземпляр их не возьмёт** — они захвачены;
- **ожидание съедает предел обработки**: аренду продлевает heartbeat, а предел — счётчик продлений
  ([0046](0046-lease-in-attempt.md)); попытка может упереться в предел, не начав работать;
- **`started_at` попытки врёт** — это время захвата, а не начала работы, и метрика времени
  выполнения включает очередь.

## Рассмотренные варианты

### A. Захватывать не больше свободных воркеров, при полном захвате — следующий без ожидания такта — выбрано

### B. Поменять значения по умолчанию, предупреждение оставить — отвергнуто

`batch-size: 8` при `workers: 8` убирает самоповтор, но при любой настройке с `batch-size`
больше `workers` проблемы возвращаются, а пропускная способность остаётся ограниченной тактом.

### C. Убрать предупреждение, принять очередь в памяти — отвергнуто

Три проблемы остаются, их просто перестают показывать.

## Решение

- **Лимит захвата — `min(batch-size, свободные воркеры пула поллера)`.** У каждого поллера свой
  пул ([0063](0063-claim-ordering-and-pollers.md)), и считаются свободные воркеры именно его.
  Свободных нет — поллер в БД не ходит. Очереди захваченного в памяти нет.
- **`batch-size` — верхняя граница одного захвата**, а не его размер.
- **Захват вернул столько строк, сколько просили, — следующий идёт сразу, как освободится
  воркер**, не дожидаясь такта: работа в очереди, скорее всего, ещё есть. Вернул меньше — очередь
  пуста, следующий захват по такту `poll.interval`. Такт — пауза для пустой очереди, а не потолок
  пропускной способности.
- **Переподхват истёкших аренд** — вторая ветка задачного захвата
  ([0067](0067-expired-lease-closes-attempt.md)) — работу не выдаёт и воркеров не занимает;
  его ограничивает только `batch-size`.
- **Проба размыкателя** ([0065](0065-communication-circuit-breaker.md)) берёт свои `k` строк
  из тех же свободных воркеров.
- **Предупреждение `batch-size > workers` из проверок при старте убирается.**

## Последствия

- **Захваченное всегда исполняется сразу**: `started_at` попытки — начало работы, предел
  обработки не тратится на ожидание, свободный экземпляр забирает всё, что не взял занятый.
- **Захватов больше, и они мельче**: при коротких задачах — почти на каждое освобождение
  воркера. Каждый — короткая транзакция с `SKIP LOCKED`; цену проверяют нагрузочные сценарии
  [0081](0081-claim-scan-filters-load-scenario.md).
- **Пропускная способность не привязана к такту**: при полной очереди экземпляр выбирает её
  так быстро, как работают воркеры.
- Значения по умолчанию остаются прежними и больше ни о чём не предупреждают.

# 0117. Хранилище задач — классы по обязанностям вместо одного `TaskRepository`

- **Дата:** 2026-10-24
- **Статус:** принято

## Контекст

[0089](0089-no-storage-spi-explicit-extension-points.md) убрал публичный SPI хранилища и оставил
в `internal` интерфейсы `TaskRepository`, `CommunicationRepository`, `ExecutionRepository`
«ради тестов и чистоты слоёв». На этапе 3 хранилище задач написано как четыре класса без
интерфейсов: создание задачи, захват, закрытие попытки, heartbeat.

## Рассмотренные варианты

- **A. Один `TaskRepository` с JDBC-реализацией** — отвергнуто. В нём собрались бы создание
  с проверкой транзакции потребителя, запрос захвата с двумя ветками, условное закрытие
  с результатом и продление аренды — сотни строк SQL разных транзакционных правил. Интерфейс
  при единственной реализации и тестах на настоящем PostgreSQL ничего не даёт.
- **B. Классы по обязанностям — выбрано**: `TaskCreator`, `TaskClaimer`, `TaskAttemptCloser`,
  `TaskHeartbeat`, общие для них `TaskRetries` и `TaskPartitionHorizon`.

## Решение

- Хранилище задач — классы в `task.internal`, каждый со своей транзакцией и своим SQL.
  Интерфейсов над ними нет: реализация одна, тесты идут на Testcontainers.
- `ExecutionRepository` остаётся одним классом: у дела две операции.
- Главное из 0089 в силе: публичного SPI нет, хранилище — внутреннее.
- Коммуникации на этапе 5 разбиваются по своим обязанностям, без оглядки на это разбиение
  ([0010](0010-separate-engines.md)).

## Последствия

- Каждый класс читается целиком вместе со своими транзакционными правилами.
- Компонентов для сборки бинов больше; собирает их автоконфигурация задач на этапе 4.
- Слова «`TaskRepository`» в описаниях больше нет; в правилах оно заменено на хранилище задач.

## Связанные решения

- [0089](0089-no-storage-spi-explicit-extension-points.md) — хранилище без публичного SPI; здесь
  меняется его форма внутри `internal`.

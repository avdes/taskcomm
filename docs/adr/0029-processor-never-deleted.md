# 0029. Процессор типа задачи не удаляется никогда

- **Дата:** 2026-08-27
- **Статус:** принято
- **Поправка:** утверждение в «Последствиях» о том, что список ломающих изменений потребителя
  не растёт, **неточно**. Изменение `json_path` или `field_type` у объявленного поля поиска ломает
  поиск по старым строкам независимо от того, жив процессор или нет. Отвергнутый вариант B этот
  запрет не создавал, а **обнаруживал** — падением при старте. Отказавшись от таблицы, мы получили
  тот же запрет, только молчаливый. См. [docs/consumer-contract.md](../consumer-contract.md).

## Контекст

[0028](0028-contract-migration.md) описывал миграцию контракта пятым шагом «удалить старый процессор
следующим релизом, когда незавершённых задач его типа не осталось». При сверке документов
выяснилось, что этот шаг конфликтует с двумя другими решениями.

Живой процессор нужен не только для выполнения задач:

- из его дженерика восстанавливается Java-тип нагрузки ([0012](0012-payload-storage.md));
- из него берётся белый список полей для поиска по нагрузке ([0016](0016-payload-search.md)).

Завершённые задачи типа лежат в БД до дропа партиции, а удаление партиций **выключено
по умолчанию** ([0020](0020-partitioning.md)). То есть после удаления процессора история этого типа
остаётся в базе, но перестаёт искаться — потенциально навсегда.

## Рассмотренные варианты

### A. Удалять после доработки незавершённых, поиск по истории теряется — отвергнуто

Исходная формулировка 0028. Задачи остаются видимыми и открываются (REST отдаёт нагрузку сырым
JSON и в десериализации не нуждается), но найти их по номеру заказа уже нельзя.

### B. Хранить белый список в БД, удалять процессор сразу — отвергнуто

Таблица `tc_search_field (task_type, level, name, json_path, field_type)`, пополняемая при старте
из реестра и никогда не чистящаяся. Поиск по истории живёт без процессора.

Отвергнуто по двум причинам. Появляется новая сущность в схеме ради справочника на десятки строк.
И, что важнее, добавляется восьмое правило в список ломающих изменений потребителя: `json_path`
и `field_type` объявленного поля нельзя было бы менять иначе как через новый тип, потому что старые
строки лежат в нагрузке старой формы.

### C. Не удалять процессор никогда — выбрано

## Решение

**Процессор типа задачи не удаляется.** Однажды заведённый тип живёт в коде столько же, сколько
существует приложение.

Удаление процессора — **ломающее изменение на стороне потребителя**, в одном ряду со сменой
контракта у живого типа и переименованием `taskType`.

Порядок миграции из [0028](0028-contract-migration.md) сокращается до трёх шагов:

1. Клонировать процессор под новым `taskType` с суффиксом версии.
2. Переключить постановку задач на новый тип.
3. Пометить старый процессор `@Deprecated` — новые задачи на него не принимаются.

Пятый шаг исчезает, четвёртый (дождаться обнуления счётчика незавершённых) остаётся полезным
для понимания, что миграция завершена, но больше ничего не гейтит.

## Последствия

- **Реестр процессоров растёт монотонно.** Через несколько лет в нём будут десятки классов,
  из которых реально принимают работу единицы. Это принятая цена, а не техдолг.
- **`@Deprecated` перестаёт быть шагом к удалению и становится постоянным состоянием.** Тип закрыт
  для новых задач и при этом остаётся в коде навсегда.
- Старый процессор **не является мёртвым кодом** в смысле «можно не поддерживать»: его `process`
  вызывается при доработке оставшихся задач, а объявление полей поиска обслуживает историю.
  Он обязан компилироваться, проходить тесты и работать.
- Дисциплина именования типов становится существеннее, чем казалась: имена накапливаются навсегда,
  и соглашение о суффиксе версии — единственное, что удерживает реестр читаемым.
- Механизм осиротевших задач ([0026](0026-contract-shape-marking.md)) остаётся, но меняет роль:
  теперь это страховка от **ошибки**, а не от штатного шага миграции.
- Ретенция перестаёт быть связанной с жизненным циклом кода. Глубина хранения — вопрос объёма
  данных и только.
- Новой таблицы в схеме не появляется, список ломающих изменений потребителя не растёт.
